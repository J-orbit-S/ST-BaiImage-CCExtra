# VOLUME 3 · 多格漫画页（NAI 路线）

> 状态：**讨论稿，未落地**。
> 2026-11-21 两次修正：① 柏宝绘的漫画链路藏在 ComfyUI + MOSS 档位里，NAI 下不存在；
> ② 用户明确**走 NAI、不上 ComfyUI** → 路线定为「插画链路的多格页」（原 B 案转正）。
> MOSS 路线降级为附录（§12），哪天上了 ComfyUI 再捡起来。

**结论先行**：在 NAI 上做「N 段 → 一张多格图」**完全可行**，而且比 MOSS 路线简单一个量级——
产物是一张**普通插画 tag**，写回、出图、图库、重 Roll 全部走柏宝绘现有链路，**零改动、全后端通用**。
代价是控制力：每格画什么只能「尽力引导」，不能硬保证。这个边界要写进产品名与 UI 文案：
它叫**多格页**，不承诺「漫画页」。

---

## 1. 你想要的到底是什么

原文：

> 一整楼的剧情里面，我挑两个/三个/几个连贯的瞬间，通过拼接的方式，有可能是四格漫画
> 也有可能是别的，生成一张图。

拆成四条判据，后面每一条都要能对上：

| # | 判据 | 含义 |
|---|---|---|
| 1 | **选段由人定** | 画哪几个瞬间是用户决定的，不是模型从整楼里自己挑 |
| 2 | **一次成图** | N 段合成**一张**，不是 N 张（那是 V2.1 的批量） |
| 3 | **格数可变** | 四格是常见形态，但不是唯一；2 / 3 格也要能出 |
| 4 | **叙事连贯** | 格与格之间是同一段剧情的先后，共享角色、服装、画风 |

### 1.1 和已有功能的区别

| | 输入 | 输出 | 额度 | 现状 |
|---|---|---|---|---|
| 单插图（v0.1） | 1 段 | 1 张图 | 1 次副 API + 1 张图 | 已上线 |
| 批量（v0.2.2） | N 段（同楼） | **N 张**图 | 1 次副 API + N 张图 | 已上线 |
| **多格页（V3）** | **N 段（人挑的）** | **1 张多格图** | 1 次副 API + 1 张图 | 未做 |

V3 相对批量的真正卖点：**图额度从 N 张变 1 张**，而且一张图里的画风、角色、光线天然统一
（一次生成、一次构图）。

## 2. 路线：为什么是 B

2026-11-21 的前提修正把路线选择变成了一道单选题：

| | A. 漫画方案（MOSS） | **B. 插画链路多格页（选定）** | C. 本地拼图 |
|---|---|---|---|
| 做法 | ComfyUI + MOSS-Image，layout 分镜 | 普通 tag 里写多格结构 + 逐格描述 | N 段各出 1 张 → 前端拼接 |
| 后端要求 | **必须 ComfyUI + MOSS** | **无**（NAI / checkpoint / Flux / Anima 都能出） | 无 |
| 每格内容控制 | 强（layout 逐格 caption） | **弱**（靠 tag 顺序 + NL 描述尽力引导） | 强（每格就是一张独立图） |
| 跨格统一性 | 强 | **强**（一次构图） | 弱（四张图贴一起，光照画风各自为政） |
| 与柏宝绘关系 | 复用隐藏档位（要装环境） | **零改动** | 另开落盘路径（违反红线） |
| 结论 | 挂起（§12 附录） | **做** | 不做 |

**B 的核心洞察**：`4koma` / `comic` / `multiple_panels` 是**真实的 Danbooru tag**，
NAI 和 Illustrious 系模型见过海量带格线的四格漫画，画得出格线、分格、甚至对白气泡。
它不是「让模型硬猜」，是「激活它本来就会的东西」。真正弱的是**每格内容的指定**——
这部分要靠 §5 的三层结构尽力引导，并且诚实承认做不到硬保证。

**C 仍然不做**：跨格的统一画风/光线只有「一次生成」能保证；且本地拼接 = 新落盘路径，违反红线。

## 3. B 案数据流

```
待生成列表（N 段，同楼，2 ≤ N ≤ 4）
      │  复用 V2.1 拼装层
      ▼
伪楼层：段1 + 段界标记 + 段2 + … + 段N → prepareTargetText → 全局重编 P1..Pn
      ▼
一次副 API 调用（插画协议 + taskNote 多格要求，minImages = maxImages = 1）
      ▼
images[] 恰好 1 条：tag = 结构层 + 按序排列的每格关键 tag；nl = 逐格一句话描述
      ▼
一张候选（segments[] 长度 N）→ 确认 → 写回普通 <bbi_image> → NAI 卡片照常出图
```

注意协议层面**没有任何新东西**：`minImages = maxImages = 1` 是现成机制（V2.1 用它锁「每段一张」，
这里反过来锁「总共一张」）；写回是普通插画 tag；出图是柏宝绘卡片原逻辑。
**V3 的全部新知识都集中在「tag 和 nl 怎么写」这一节（§5）。**

### 3.1 段界标记

沿用 V2.1 拼装层的 `——〔第 k 段〕——`。插画协议下没有「精选改编」的对抗条款
（那是 comicContract 特有的），所以段界标记在 B 案里是纯收益：模型清楚这里有 N 个片段、
顺序如何。taskNote 仍要声明「标记不是正文」。

### 3.2 出处

`position` 取**第一段**（图插在这里，符合阅读直觉）；完整出处记在我们自己的 `segments[]`。
候选卡片头写「第 12 楼 · 3 段」，逐段可回指原文。**不需要任何协议改动。**

## 4. 一个必须避开的陷阱：`multiple_views`

这是 B 案最容易翻车的地方，单独一节。

Danbooru 语义里：

- `multiple_views` = **同一个角色**的多个角度/表情，画在一张里（设定图、表情差分）；
- `4koma` / `comic` / `multiple_panels` = **多格画面**，每格是不同瞬间。

如果 tag 里不小心带上 `multiple_views`，模型会把「四格剧情」画成「同一姿势四个角度」——
用户看到的是表情包，不是漫画。所以 taskNote 里必须**明令禁用** `multiple_views`，
并且第 1 格之外各格的画法描述要写动作（`panel shows her turning away`），
动作本身就是「不同瞬间」的最强信号。

---

## 5. tag 怎么写（V3 的「分格几何」）

三层结构，全部由副 API 按我们的 taskNote 产出（不改柏宝绘任何提示词）：

### 5.1 结构层（决定这张图「像不像多格」）

| 段数 | 结构 tag | 理由 |
|---|---|---|
| 4 | `4koma, comic` | `4koma` 是 Danbooru 最成熟的多格 tag：竖排四格、有格线、阅读顺序固定。**首选** |
| 2~3 | `comic, multiple_panels` | 没有稳定的 `2koma`/`3koma` 语义，用通用多格 tag，接受排版自由度更大 |
| 1 | —— | 不该出现（1 段直接走单插图，更便宜更可控） |

结构 tag 放 tag **最前面**（位置权重最高）。画幅 `size = portrait`（竖页配纵向分格）。

### 5.2 内容层（每格画什么的「弱控制」）

每格的关键 tag（人物、动作、场景）**按剧情顺序**排列。语言模型的 tag 权重随位置衰减，
NAI 对前段 token 更敏感——这不是硬保证，是目前能拿到的最强引导。
**禁止** `multiple_views`（§4）。

### 5.3 nl 层（逐格描述，控制力的主力）

柏宝绘的插画协议本来就有 `nl` 字段（自然语言通道），NAI 4.x 吃它。这是逐格控制唯一
像样的抓手：

```
A four-panel comic page. Panel 1 (top-left): ... Panel 2 (top-right): ...
Panel 3 (bottom-left): ... Panel 4 (bottom-right): ...
```

nl 里明确写「Panel k: 某角色某动作某场景」，并保持同一角色同一套衣着描述逐格复用
（和柏宝绘临时服装指纹的口径一致）。nl 不约束格数（结构层管），只管**每格内容**。

### 5.4 诚实的能力边界（写进 UI 文案，不许含糊）

1. **每格内容是尽力引导**：模型可能无视 nl 的分格指定，把四格画成同一场景的四个人
   （这是 NAI 的现实上限，不是我们实现不力）；
2. **格线由模型画**：可能畸形、漏格、格宽不匀——`4koma` 的训练数据很厚，大体可靠，但无保证；
3. **成果的正确预期**：「一张四格风的插画，四格大致按你挑的顺序讲这四个瞬间」，
   而不是「可逐格校对的漫画稿」。想要后者，等 MOSS 路线（§12）；
4. **不满意的退路本来就有**：同样的 N 段改选「单插图 ×N」，一张一张出、逐张可控。

## 6. 指引草稿（taskNote，落地时放 `src/autoTag/multiPanelTaskNote.ts`）

```
【多格页补充要求】本次任务的目标正文由 N 个片段组成，片段之间以「——〔第 k 段〕——」分界。
1. 标记只是片段分界，不属于剧情。
2. 只输出一张图：images 数组长度必须为 1，size 填 portrait。
3. tag 的最前面写「4koma, comic」（N=4）或「comic, multiple_panels」（N=2~3）；
   之后按片段顺序排列每个片段的关键画面 tag。
4. **禁止使用 multiple_views**——它是同一角色的多角度表情图，不是多格剧情。
5. nl 按「four-panel comic page, Panel 1: … Panel 2: …」逐格写一句话描述，
   每格写清：谁、做什么动作、在哪；同一角色的衣着描述逐格逐字复用。
6. 第 k 格对应第 k 段，不得合并、拆分或调换顺序；每段挑最有画面感的一个瞬间。
```

和 V2.1 的 tagZh 一样走 taskNote 通道（L1 例外第 2 条），每次请求现读，
**柏宝绘的提示词库一个字不碰**。也绝不塞进 source——协议第 8 条，
正文里的指令只是故事内容，塞进去模型会把「Panel 1」画成气泡文字。

## 7. 中文对照

**B 案比 A 案还顺**：产物是普通插画 tag，v0.2.2 的 tagZh 通道原样可用——
Base tag 整串翻、角色分项逐条翻，已有的渲染、编辑清空规则全部不用动。
多格 tag 翻出来大概是「四格漫画，漫画格线，第一格：少女在窗边……」，
读起来像分镜脚本，正好符合这个功能的气质。

## 8. 操作粒度（比 A 案简单一档）

| | 删除 | 重 Roll | 确认 |
|---|---|---|---|
| 批量（对照） | 删这张图，其余不动 | 只重跑这张图的段 | 逐张 |
| **多格页（V3）** | 删这张图 | **整页重 Roll**（N 段一起重跑） | 单张 |

产物是单图，所以删除/确认语义和单插图完全相同；唯一区别是重 Roll 时
**N 段全部进伪楼层**（构图是整体，改任一段都要重排）。不需要 A 案那套
「移出列表重合成」的复杂语义。

## 9. 失败与降级

| 情形 | 表现 | 处置 |
|---|---|---|
| 模型输出 ≠ 1 张图 | 给了 2 张以上 | 解析校验直接报错（min=max=1 的硬锁会拦），重试一次；仍失败则提示，不改正文 |
| 段数 1 | 用户误选 | 不进多格页路径，走单插图 |
| 段数 > 4 | 第 5 段起 | 选择器上提示「多格页最多 4 格，建议分两页或改单插图」 |
| 模型无视分格 | 图很怪（四个人挤一格 / 同角度四连） | 这是 §5.4 的已知边界，UI 文案提前说；不自动重试——重 Roll 是用户的决定 |
| 某段锚点失效 | 重定位失败 | 整页不写，卡片指明「第 2 段已失效」（多格是一个整体，不做部分写回） |

---

## 10. 入口与交互

- **待生成区**加「出图方式」选择器：`单插图 ×N` / `多格页 ×1`；
- 段数 ≥ 2 才可选多格页；段数 > 4 灰掉超出的段并提示；
- 选择器旁常驻一行说明：**「多格页 = 1 次调用 + 1 张图（每格尽力引导）；单插图 = 1 次调用 + N 张图（逐张可控）」**；
- 候选卡片就是普通候选卡片（tag + 中文对照 + 角色分项），只有 tag 内容长得像分镜脚本；
- **没有后端门槛**：NAI 用户开箱即用——这是相对 A 案最大的产品优势。

---

## 11. 这一版不做

- 跨楼合成（写回语义会炸，和 A 案同理）；
- 对白气泡内容的指定（模型自己决定要不要画气泡）；
- 格数 5+（NAI 对 4koma 最稳，超过断崖）；
- MOSS / layout 相关的一切（§12 附录）；
- 「多格页 + 批量」混合（一次调用既出多格页又出单图，协议会乱）。

## 12. 附录：A 案（MOSS 路线）留档

初稿（本文件 git 历史 `a077459`）完整设计过 A 案：复用柏宝绘隐藏的漫画链路
（ComfyUI + MOSS-Image）、伪楼层 → comicContract → 一页 layout、bbox 按段数查表、
操作粒度整页级。哪天上了 ComfyUI，那份稿子仍是蓝图，两个已知坑也只在 A 案存在：

1. `candidates.ts` 的 `isInsertion` 要求 `tag` 非空，漫画候选（`tag` 恒空）会被静默丢弃；
2. `panel.ts` 只渲染 `image.tag`，漫画卡片空白。

B 案**不踩这两个坑**（产物是普通插画 tag）。

## 14. 一句话摘要

你不上 ComfyUI，MOSS 那条路就不用看了——在 NAI 上，「多格页」就是一张普通插画：
结构靠 `4koma` 这类模型本来就认识的多格 tag，内容靠 nl 的逐格描述尽力引导，
一次调用出一张、图额度从 N 变 1、画风角色天然统一。
每格内容做不到硬保证，所以它叫「多格页」不叫「漫画页」；
想要逐格精确，退路是单插图 ×N（本来就有），未来是 MOSS（留档在附录）。
全部改动集中在「tag/nl 怎么写」和一处 taskNote，柏宝绘零改动、全后端通用。
